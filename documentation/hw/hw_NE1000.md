# `hw.NE1000`

`hw.NE1000` connects EPsych to a
[New Era NE-1000 Multi-Phaser™](https://www.syringepump.com) programmable
syringe pump over RS-232, speaking the pump's Basic-mode ASCII protocol
directly (user manual #1200-01, firmware V3.923, sec. 10).

It is the backend to reach for when a paradigm meters liquid reward from a
syringe pump: set a `Rate` and a `Volume`, pulse `Start`, and the pump
dispenses that volume and stops itself. The pump owns the dispense timing; the
host only configures and triggers.

```matlab
iface = hw.NE1000('COM4');
iface = hw.NE1000('', AutoDetect=true, SyringeDiameter=21.59);  % probe ports for a pump
iface = hw.NE1000('COM4', Connect=false);                       % offline, for ProtocolDesigner
iface = hw.NE1000('COM4', Address=3, BaudRate=9600);            % pump network member

iface.set_parameter('Rate', 0.5);      % in RateUnits (default mL/hr)
iface.set_parameter('Volume', 0.05);   % 0 = continuous pumping until Stop
iface.trigger('Start');
iface.trigger('Stop');
```

> **Status: under development.** The protocol layer is exercised by
> `tmp/smoke_test_ne1000.m` against an in-process mock
> (`tmp/NE1000_Mock.m`); it has not yet been validated against a physical

## The wire protocol

Every exchange is one synchronous transaction. The host sends a CR-terminated
command, optionally prefixed with the pump's 0–99 network address; the pump
answers with a single packet:

```
<STX> <address> <status> [data] <ETX>
```

- `STX` = 0x02, `ETX` = 0x03. The serialport handle is configured with a read
  terminator of 0x03 and a write terminator of CR, so `writeline`/`readline`
  frame both directions.
- `status` is one prompt character reported with *every* reply:
  `I`nfusing, `W`ithdrawing, `S`topped, `P`aused, `T`imed pause,
  `U` (trigger wait), `X` (purging) — or `A?<code>` for an alarm
  (`R` reset, `S` stall, `T` comm timeout, `E` program error, `O` phase out of
  range).
- Command errors ride in the data field as `?`, `?NA`, `?OOR`, `?COM`, `?IGN`.
- Numeric command data is limited to **4 digits plus one decimal point**;
  `hw.NE1000.formatFloat_` renders every outgoing float to fit.

Three protocol subtleties the implementation handles for you:

1. **Safe-mode escape.** A pump left in Safe mode (CRC-framed packets) ignores
   bare ASCII. `connect()` first sends the documented escape packet
   (`0x02 0x08 SAF0 0x55 0x43 0x03`, manual 10.2.2), which returns it to Basic
   mode and is accepted harmlessly when already there.
2. **Power-up alarm.** A pump fresh from a power cycle answers its *first*
   command with `A?R` instead of data. Per the manual, that reply *is* the
   acknowledgment, so the handshake simply repeats its `VER` query. Alarms
   seen at any point are logged through `vprintf` and recorded in `LastAlarm`.
3. **Rate units mid-run.** Units cannot be changed while pumping, so a `Rate`
   write first tries `RAT<value><units>` and falls back to the bare value when
   the pump rejects the units form with `?NA`.

Failures degrade rather than throw: a timeout or error reply warns through
`vprintf` and the session continues, following the house rule that a flaky
cable must not abort a run mid-trial.

## What this backend deliberately does not do

The NE-1000's Pumping Program — Phases, loops, event traps, sub-programs — is
**not modeled**. This interface drives the pump as a single-rate dispenser,
which covers reward delivery: `RATE` with a volume target in Phase 1 stops by
itself. If a paradigm genuinely needs a multi-Phase program, author it with
PUMPTERM / SyringePumpPro or the keypad; `Start`/`Stop` here still run it, but
the parameter table only reflects the currently-selected Phase.

The TTL logic interface (foot switch, event triggers, direction input) is also
untouched; wire it directly to your rig hardware if used. Note the pump's
`LE` (level control) trigger mode pairs naturally with a TDT digital output
for hardware-timed reward — that path needs no host round-trip at all.

## Construction

| Option | Default | Meaning |
|---|---|---|
| `port` | `''` | Serial port, e.g. `COM4`. Machine-specific; a saved protocol may need it corrected on another rig. |
| `AutoDetect` | `false` | Probe available ports for a pump answering `VER` at the configured address/baud. |
| `Address` | `0` | Pump network address 0–99. A single pump is 0 (factory default). |
| `BaudRate` | `19200` | Must match the pump's Setup value. 300/1200/2400/9600/19200. |
| `SyringeDiameter` | `0` | Inside diameter (mm) pushed at connect. **0 keeps the pump's stored value.** Scales every rate and volume the pump computes (manual sec. 12.7 lists diameters per syringe brand/size). |
| `RateUnits` | `'MH'` | Units attached to `Rate` writes: `MH`=mL/hr, `MM`=mL/min, `UH`=µL/hr, `UM`=µL/min. |
| `Connect` | `true` | Pass `Connect=false` for offline construction (serialization, ProtocolDesigner). |
| `Timeout` | `1` | Transaction timeout in seconds. |

### Connect sequence

1. Resolve the port (`findPumpPort` when `AutoDetect` or empty).
2. Open at 8N1, read-terminator ETX, write-terminator CR.
3. Send the Safe-mode escape packet; flush.
4. `VER` handshake (retried once when the reply carried a power-up alarm);
   the reply becomes `FirmwareVersion`.
5. `STP` — stop anything a previous session or Power Failure mode left
   running, before touching settings (most setters are rejected while the
   program operates).
6. Push `SyringeDiameter` when non-zero.
7. Build (or merge into) the single `Pump` module's parameter table.

## Parameters

One `hw.Module` (`Pump`) holds ten parameters. Following the Visible/Access
matrix (see `hw.Bpod`'s documentation for the derivation):

| Name | Access | Visible | Wire | Meaning |
|---|---|---|---|---|
| `Rate` | Any | yes | `RAT` | Pumping rate in `RateUnits`. Trial-table column; recorded in DATA. |
| `Volume` | Any | yes | `VOL` | Volume to dispense per `Start`; 0 = continuous. Trial-table column; recorded in DATA. |
| `VolumeInfused` | Read | yes | `DIS` | Accumulated infused volume. Recorded in DATA. |
| `VolumeWithdrawn` | Read | yes | `DIS` | Accumulated withdrawn volume. Recorded in DATA. |
| `Direction` | Any | no | `DIR` | `Infuse` / `Withdraw` (also `Reverse`, `Sticky`). Operator-facing. |
| `Diameter` | Any | no | `DIA` | Syringe inside diameter, mm. Settable only while stopped. |
| `Status` | Read | no | — | Live prompt character mapped to a label (`Infusing`, `Stopped`, …, `Alarm:<code>`). |
| `Start` | trigger | no | `RUN` | Start/resume the pump. |
| `Stop` | trigger | no | `STP` | Stop (pause) the pump; a second Stop resets to Phase 1. |
| `ClearVolume` | trigger | no | `CLD` | Zero both dispensed-volume accumulators (valid only while stopped). |

`VolumeInfused` and `VolumeWithdrawn` are served from one shared `DIS` query
cached for `DispenseCacheInterval` (50 ms), so the runtime's per-trial DATA
sweep costs a single round-trip. The pump picks the units it reports them in
from the **syringe diameter** — µL below 14 mm, mL at or above — not from
anything the host sets, so a display that labels them reads
`DispensedUnits` (`'UL'`/`'ML'`, recorded from the last `DIS` reply) rather
than assuming `RateUnits` applies.

The pump resets its dispensed-volume accumulators on power-up, on a diameter
change, and on rollover at 9999 — treat per-trial *differences* of
`VolumeInfused` as the trustworthy quantity, not the absolute value.

### A per-trial reward pattern

```matlab
% trial setup (runtime writes via the trial table)
%   Rate   <- reward rate for this trial
%   Volume <- reward size for this trial
% at reward time (e.g. from a custom TrialSelector or BoxGUI):
RUNTIME.Interfaces(k).trigger('Start');   % pump stops itself after Volume
```

### The operator panel

[`gui.SyringePump`](../gui/gui_SyringePump.md) is the front end for everything
above: a dispensed-volume readout, a port picker with auto-detect, and
controls for diameter, rate, and infuse/withdraw, embeddable in a custom
BoxGUI with `obj.addSyringePump(panel)` or usable on its own. It works
against a protocol's pump or an interface it makes itself, so a pump can be
primed and set up with no session running.

## Safety

- **Teardown stops the pump.** `disconnect`, `delete`, and any `mode`
  transition into Idle/Stop/Error all issue `STP`. The pump executes its
  program with no host attached, so dropping the port without stopping would
  leave an infusion running until the syringe stalls.
- **Purge is not exposed.** `PUR` drives the pusher at top speed until
  explicitly stopped; use the keypad (hold Start/Stop) with eyes on the rig.
- **Not for clinical use on humans** — the manufacturer's warning applies to
  everything this backend does.

## Testing

`tmp/smoke_test_ne1000.m` runs the full protocol path against
`tmp/NE1000_Mock.m`, which overrides only the transport seam
(`openPort_` … `flushInput_`), so the framing, parser, alarm handling, units
fallback, and DIS cache are the same code a real pump executes:

```matlab
matlab -batch "run('tmp/smoke_test_ne1000.m')"
```
